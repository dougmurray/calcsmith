# CLAUDE.md

This file provides guidance to Claude Code (claude.ai/code) when working with code in this repository.

## Project Overview

Calcsmith is a personal engineering calculator for macOS and iPhone, built in SwiftUI from one codebase. It has two modes: a scientific calculator (the default), which shows results in engineering notation (`4.7e-6` → `4.7μ`), and a searchable formula library ported from the Rust TUI at `../analog_engineer_assistant`. In the formula library, Tab / ⇧Tab changes the subject of the formula (the variable being solved for).

## Commands

```bash
swift build                                   # build the package (macOS)
swift test                                    # run all core tests (Swift Testing)
swift test --filter FormulaLibraryTests       # one suite
swift test --filter FormulaLibraryTests/variantsInvertEachOther   # one test

xcodegen generate                             # regenerate Calcsmith.xcodeproj after editing project.yml or adding files under Apps/
xcodebuild -project Calcsmith.xcodeproj -scheme Calcsmith-macOS -derivedDataPath .build/xcode build
xcodebuild -project Calcsmith.xcodeproj -scheme Calcsmith-iOS -destination 'generic/platform=iOS Simulator' -derivedDataPath .build/xcode build

# Re-sync formulas from the Rust app (OVERWRITES every file in Sources/CalcsmithCore/Formulas/)
python3 tools/port_formulas.py ../analog_engineer_assistant Sources/CalcsmithCore/Formulas
```

The iOS scheme needs a simulator destination. Building for a device fails until a development team is set. No linter or formatter is configured.

## Architecture

The code has three layers. Swift tools 6.0, strict concurrency, minimum macOS 15 / iOS 18.

- **`Sources/CalcsmithCore`**: platform-independent logic. Has no SwiftUI dependency, and it is the only target with tests.
  - `ExpressionEvaluator`: a lexer plus a recursive-descent parser that evaluates while it parses. It handles SI-prefix suffixes glued to numbers (`4.7k`, `10u`), implicit multiplication, the parallel operator `||`/`∥`, postfix `!`/`%`, and `ans`, which is passed in through `variables`. A prefix letter counts as a suffix only if no further identifier character follows it, so `2pi` parses as 2×π.
  - `EngineeringFormatter`: `format` (SI prefixes from q to Q) and `quantity`, which leaves units that already carry a prefix (`mm`, `pF`, `nH`, …) and dimensionless units as plain numbers.
  - `Formula` / `Variant` / `Var` / `Topic`: the formula model. Each `Variant` is one solve-for rearrangement. Its `compute` closure receives inputs **in the order of `inputs`**.
  - `FormulaSession`: per-formula state. Input text is keyed by **symbol**, so values carry over when the variant changes. `selectVariant` writes the current result into the old subject's field. Input fields go through the full expression evaluator, after stripping a trailing unit (`4.7uF`, `10 kΩ`).
  - `FormulaLibrary`: lists the topics and provides `search`. Each query term scores highest as a substring match at a word start. Hits in the formula name are weighted ×2 above hits elsewhere. Loose subsequence matches are dropped below a quality threshold.
  - `Formulas/*.swift`: one file per topic, generated by `tools/port_formulas.py`. The closures keep Rust method syntax (`.sqrt()`, `.ln()`, `.powi()`), which `RustMath.swift` provides as `Double` extensions.
- **`Sources/CalcsmithUI`**: SwiftUI views shared by both platforms. Platform differences live inside the shared files under `#if os(macOS)` / `#if os(iOS)`, not in separate view files.
  - The `@Observable @MainActor` models are `CalculatorModel` (expression, history kept in UserDefaults, angle mode) and `FormulaStore` (query, selection, sessions, focus requests).
  - `CalcsmithRootView` switches modes. On macOS it uses a toolbar picker, with ⌘1 / ⌘2 / ⌘F handled by invisible shortcut buttons. On iOS it uses a `TabView`. The mode is stored in `@AppStorage("app.mode")`.
- **`Apps/macOS`, `Apps/iOS`**: tiny `@main` entry points only. `project.yml` (XcodeGen) builds both app targets against the local package product `CalcsmithUI`.

## Non-obvious decisions

- **Tab on macOS** is caught by an `NSEvent` local monitor (`TabMonitor` in `FormulaDetailView.swift`), because text fields consume Tab for focus traversal before SwiftUI's `onKeyPress` sees it. iOS uses `onKeyPress(.tab)`.
- **macOS formula search** is a plain `TextField`, not `.searchable`: the sidebar search field swallowed Return, and `onSubmit(of: .search)` never fired. ↑/↓ call `FormulaStore.moveSelection`. Return calls `openSelectedOrTopResult`, which focuses the inputs through `requestInputFocus()`: a counter for `onChange` plus an `inputFocusPending` flag for a freshly appearing detail view. This stops a newly selected detail view from stealing focus from the search field while the user types.
- **The Mac calculator** focuses its `TextField` at launch, so typing goes straight in. `CalculatorModel.textDidChange` treats a typed `=` as evaluate. Typing an operator right after evaluating prepends `ans`. Keypad buttons use `.focusable(false)` and refocus the field after a press.
- **Lexer digits** use `Lexer.isDigit` (ASCII only), because `Character.isNumber` also matches `²`, `½`, and similar characters.
- **Swift type-checker**: large literal tables can time out it. Keep parameterized-test argument lists in a typed `static let`, and write formula arithmetic with `1.0` rather than `1`.

## Adding formulas

Add a `Formula` / `Variant` directly to the matching file in `Sources/CalcsmithCore/Formulas/`. To add a new topic, also register it in `FormulaLibrary.topics`, and in `TOPICS` in the porter script if the topic should stay synced with the Rust app. Use the same symbol for a quantity in every variant of a formula, so its value carries over on Tab.

After any change, update the hard-coded topic/formula/variant counts in the `portedEverything` test, then run `swift test`. `variantsInvertEachOther` checks that rearranged variants agree with each other, and `defaultsProduceFiniteResults` catches bad defaults.

Don't re-run the porter after hand-editing formula files unless you mean to discard those edits. A fuller local guide is at `docs/adding-formulas.md`, which is gitignored and may not exist in every checkout.
